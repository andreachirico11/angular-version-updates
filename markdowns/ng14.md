# Angular 14 

## 🔒 Reactive Typed Forms

### Strongly Typed Forms with Complex Types
Angular 14 introduces **strictly typed reactive forms**, allowing you to define complex type structures for your entire form hierarchy.

### Complete Type Safety Example
See the example in `app.component.ts`:

```typescript
// Define your type structure
interface ItemForm<T> {
  quantity: FormControl<number>;
  item: FormGroup<T>;
}

interface ShirtForm {
  color: FormControl<Color>;
  size: FormControl<Size>;
  text: FormControl<string>;
}

// Create fully typed form
formGroup = new FormGroup<ItemForm<ShirtForm>>({
  quantity: new FormControl<number>(1, { nonNullable: true }),
  item: new FormGroup<ShirtForm>({
    color: new FormControl(Color.Green, { nonNullable: true }),
    size: new FormControl(Size.medium, { nonNullable: true }),
    text: new FormControl('hello world 🌎', { nonNullable: true }),
  }),
});
```

### Accessing Controls: Before vs. After

**Before Angular 14 (String-based access):**
```typescript
// Had to use string literals - no type safety!
private itemControlsOld = this.formGroup.controls['item'].controls;
// TypeScript can't validate 'item' string
// Prone to typos and refactoring errors
```

**Angular 14+ (Type-safe access):**
```typescript
// Direct property access with full type inference!
private itemControlsNew: FormGroupAlike<Shirt> = 
  this.formGroup.controls.item.controls;
// 'item' is a property name, fully type-checked
// IDE autocomplete works perfectly
// Refactoring is safe
```

### Type-Safe Form Values

**Getting Raw Values with Types:**
```typescript
// The return type is automatically inferred!
const rawValueTyped: Item<Shirt> = this.formGroup.getRawValue();

// Now you have full type safety:
console.log(rawValueTyped.quantity); // number
console.log(rawValueTyped.item.color); // Color enum
console.log(rawValueTyped.item.size); // Size enum
console.log(rawValueTyped.item.text); // string
```

### NonNullable Option
```typescript
// With nonNullable: true, the value is never null
const control = new FormControl<string>('default', { nonNullable: true });
const value: string = control.value; // Always string, never null!

// Without nonNullable (default behavior)
const nullableControl = new FormControl<string>('');
const nullableValue: string | null = nullableControl.value; // Can be null
```

### Benefits
- **Full type inference**: no string-based access needed
- **Autocomplete**: IDE suggests available controls
- **Refactoring safety**: renaming properties updates everywhere
- **Complex type structures**: support for nested forms and custom types
- **Compile-time validation**: catch errors before runtime

### Practical Use Case
```typescript
enum ProductType {
  Shirt = 'SHIRT',
  Pants = 'PANTS',
  Shoes = 'SHOES'
}

interface OrderForm {
  customerName: FormControl<string>;
  productType: FormControl<ProductType>;
  quantity: FormControl<number>;
}

const orderForm = new FormGroup<OrderForm>({
  customerName: new FormControl('', { nonNullable: true }),
  productType: new FormControl(ProductType.Shirt, { nonNullable: true }),
  quantity: new FormControl(1, { nonNullable: true })
});

// Type-safe access
const quantity = orderForm.controls.quantity.value; // number, never null
const type = orderForm.controls.productType.value; // ProductType enum
```

## 📄 Page Title and Custom Strategy

### Custom Title Strategy Service
Angular 14 allows you to create a **custom service** to manage page titles in a centralized way, providing full control over how titles are set and formatted.

### Creating a Custom Title Strategy
You can now inject a custom strategy into the providers:

```typescript
// app.config.ts or app.module.ts
providers: [
  { provide: TitleStrategy, useClass: TemplatePageTitleStrategy }
]
```

### Implementation Example
See the example in `titleStrategy.ts`:


### Advanced Custom Strategy
```typescript
@Injectable({ providedIn: 'root' })
export class CustomTitleStrategy extends TitleStrategy {
  constructor(
    private readonly title: Title,
    private authService: AuthService
  ) {
    super();
  }

  override updateTitle(routerState: RouterStateSnapshot): void {
    const title = this.buildTitle(routerState);
    const user = this.authService.currentUser;
    
    if (title) {
      // Add user context to title
      const suffix = user ? ` | ${user.name}` : '';
      this.title.setTitle(`${title}${suffix} - Company Name`);
    }
  }
}
```

### Route Configuration with Titles
```typescript
const routes: Routes = [
  {
    path: 'dashboard',
    component: DashboardComponent,
    title: 'Dashboard' // Will become "My App - Dashboard"
  },
  {
    path: 'profile',
    component: ProfileComponent,
    title: 'User Profile' // Will become "My App - User Profile"
  },
  {
    path: 'settings',
    component: SettingsComponent
    // No title = uses default from strategy
  }
];
```


## 🛡️ Protected Bindings

### Enhanced Template Access Control
Before Angular 14, binding to protected properties in templates would cause compiler errors. Now, **protected properties are accessible in templates** while maintaining proper encapsulation.

### The Problem Before Angular 14
```typescript
@Component({
  selector: 'app-child',
  template: `<h1>{{ protectedName }}</h1>` // ❌ Compiler error!
})
export class ChildComponent {
  protected protectedName = 'John'; // Not accessible in template
}
```

### The Solution in Angular 14+
```typescript
@Component({
  selector: 'app-child',
  template: `
    <h1>{{ protectedName }}</h1>
    <p>{{ protectedEmail }}</p>
    <button (click)="protectedMethod()">Click</button>
  `
})
export class ChildComponent {
  // ✅ Now accessible in template!
  protected protectedName = 'John';
  protected protectedEmail = 'john@example.com';
  
  protected protectedMethod(): void {
    console.log('Method called');
  }
}
```

### Key Improvements

**1. Child Component Benefits:**
```typescript
@Component({
  selector: 'app-product',
  template: `
    <div>
      <h2>{{ productName }}</h2>
      <p>{{ formattedPrice }}</p>
      <button (click)="addToCart()">Add to Cart</button>
    </div>
  `
})
export class ProductComponent {
  // Used in template but not exposed to parent
  protected productName = 'Laptop';
  protected formattedPrice = '$999.99';
  
  protected addToCart(): void {
    // Implementation
  }
  
  // Truly private - not accessible anywhere
  private internalId = 'PROD-123';
}
```

**2. Parent Component Cannot Access Protected Members:**
```typescript
@Component({
  selector: 'app-parent',
  template: `
    <app-product #productRef></app-product>
    <!-- ❌ Cannot access protected members from parent -->
  `
})
export class ParentComponent {
  @ViewChild('productRef') product!: ProductComponent;
  
  ngAfterViewInit() {
    // ❌ Error: 'productName' is protected
    console.log(this.product.productName);
    
    // ❌ Error: 'addToCart' is protected
    this.product.addToCart();
  }
}
```

### Access Level Comparison

```typescript
export class MyComponent {
  // PUBLIC - accessible everywhere
  public publicProp = 'accessible everywhere';
  
  // PROTECTED - accessible in template and child classes
  protected protectedProp = 'accessible in template';
  
  // PRIVATE - only within this class
  private privateProp = 'truly private';
}
```


## 🧩 New Functions to Create Components

### Improved Dynamic Component Creation API
Angular 14 introduces **new functions for creating dynamic components** with more control over dependency injection and component lifecycle.

### The New Approach
See the example in `page1.component.ts`:

**Key Differences:**
- Create the component using new APIs
- Choose which injector to use
- Attach to view container manually
- More granular control over component creation

### Old API (Angular 13)
```typescript
export class OldComponent {
  constructor(
    private viewContainer: ViewContainerRef,
    private injector: Injector
  ) {}

  createComponent() {
    // Direct creation, less control
    const componentRef = this.viewContainer.createComponent(DynamicComponent);
  }
}
```

### New API (Angular 14)
```typescript
import { createComponent, EnvironmentInjector } from '@angular/core';

export class Page1Component {
  constructor(
    private viewContainer: ViewContainerRef,
    private environmentInjector: EnvironmentInjector,
    private injector: Injector
  ) {}

  createDynamicComponent() {
    // Step 1: Create component with custom injector
    const componentRef = createComponent(DynamicComponent, {
      environmentInjector: this.environmentInjector,
      elementInjector: this.injector
    });
    
    // Step 2: Attach to view
    this.viewContainer.insert(componentRef.hostView);
    
    // Step 3: Set inputs/outputs if needed
    componentRef.instance.someInput = 'value';
    componentRef.instance.someOutput.subscribe(data => {
      console.log(data);
    });
  }
}
```

### Choosing the Right Injector

**`environmentInjector`** - For app-level services:
```typescript
const componentRef = createComponent(MyComponent, {
  environmentInjector: this.environmentInjector // Root/Module services
});
```

**`elementInjector`** - For component-level services:
```typescript
const componentRef = createComponent(MyComponent, {
  environmentInjector: this.environmentInjector,
  elementInjector: this.injector // Component-specific services
});
```

### Complete Example with Custom Injector
```typescript
import { createComponent, Injector } from '@angular/core';

export class AdvancedDynamicComponent {
  constructor(
    private viewContainer: ViewContainerRef,
    private environmentInjector: EnvironmentInjector,
    private parentInjector: Injector
  ) {}

  createWithCustomServices() {
    // Create custom injector with specific services
    const customInjector = Injector.create({
      providers: [
        { provide: CustomService, useValue: new CustomService('custom') },
        { provide: API_URL, useValue: 'https://api.custom.com' }
      ],
      parent: this.parentInjector
    });

    // Create component with custom injector
    const componentRef = createComponent(DynamicComponent, {
      environmentInjector: this.environmentInjector,
      elementInjector: customInjector
    });

    // Set component properties
    componentRef.setInput('title', 'Dynamic Title');
    
    // Attach to view at specific index
    this.viewContainer.insert(componentRef.hostView, 0);
    
    // Component lifecycle
    componentRef.changeDetectorRef.detectChanges();
  }

  destroyComponent(componentRef: ComponentRef<any>) {
    // Clean up
    const index = this.viewContainer.indexOf(componentRef.hostView);
    if (index !== -1) {
      this.viewContainer.remove(index);
    }
    componentRef.destroy();
  }
}
